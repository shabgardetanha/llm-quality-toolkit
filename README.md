# llm-quality-toolkit

[![CI](https://github.com/yourname/llm-quality-toolkit/actions/workflows/ci.yml/badge.svg)](https://github.com/yourname/llm-quality-toolkit/actions)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Python 3.9+](https://img.shields.io/badge/python-3.9+-blue.svg)](pyproject.toml)

**Quality evaluation for `llama.cpp` — with server-config capture and extraction validation.**

A single-file-like toolkit that runs GSM8K against any OpenAI-compatible server
(typically `llama.cpp`), captures the server's **actual** configuration from
`GET /props`, and stores every run as a JSON artifact that can be re-evaluated
later without re-invoking the model.

## The problem this solves

Three independent sources of "empty numbers" (fake benchmark results):

| Layer | How it fails silently | How this toolkit fixes it |
|-------|----------------------|---------------------------|
| **Engine** | `--spec-type draft-mtp` silently falls back to `ngram-simple` | Records `/props` so drift is visible |
| **Config** | `--presence-penalty 0` in the file; server uses `0.5` | Auto-captures real values from the server |
| **Measurement** | Extraction regex misses `**bold**` final answers | Multi-format extractor validated on real Qwen output |

See [`docs/extraction-bug.md`](docs/extraction-bug.md) for a real case study:
the same model scored **62% → 35% → 90%** across three extractor versions.

## Configuration

The CLI reads three environment variables, all optional:

| Variable | Purpose | Default |
|----------|---------|---------|
| `LLM_ENDPOINT` | Chat-completions URL | `http://127.0.0.1:8080/v1/chat/completions` |
| `LLM_MODEL` | Model alias sent in the request body | `Qwen3.5-4B` |
| `LLM_API_KEY` | Bearer token for authenticated servers | *(none)* |
| `LLAMA_ENDPOINT` / `LLAMA_API_KEY` | Fallback names for the two above | *(none)* |

Copy `.env.example` to `.env` and edit, or export variables in your shell.
Command-line flags always override environment variables.

**Security note:** the API key is **never** written to the run JSON.
Only `"api_auth": true` is recorded, so reports can be safely committed.

## Usage

### Run a baseline (local server, no auth)

```bash
llm-quality run --label baseline --n 20 \
  --endpoint http://127.0.0.1:8080/v1/chat/completions \
  --model Qwen3.5-4B \
  --notes "default config, greedy"
```

### Change the server config and run again

```bash
# (restart llama-server with different flags)
llm-quality run --label reasoning-on --n 20 \
  --notes "reasoning enabled, temp=0.6"
```

### Run against a remote server with an API key

```bash
# Option 1: environment variables (safest — stays out of shell history)
export LLM_API_KEY=sk-xxxxxxxxxxxx
export LLM_ENDPOINT=https://api.example.com/v1/chat/completions
llm-quality run --label remote --n 20 --model qwen3.5-4b

# Option 2: explicit flag
llm-quality run --label remote --n 20 \
  --endpoint https://api.example.com/v1/chat/completions \
  --api-key sk-xxxxxxxxxxxx \
  --model qwen3.5-4b

# Option 3: custom headers (e.g. behind a reverse proxy)
llm-quality run --label proxy --n 20 \
  --header "X-API-Key: abc" \
  --header "X-Org: research"
```

### Compare and save a Markdown report

```bash
llm-quality compare --out ~/report.md
cat ~/report.md
```

### Re-extract without re-running the model

```bash
llm-quality re-extract '~/gsm8k_results/runs/baseline_*.json' --label baseline-v4
```

Because the raw model output is preserved in every run file, re-extraction
takes seconds and never invokes the server.

### List all runs

```bash
llm-quality list
```

## Generating the test fixture

The unit tests include a regression check on **20 real Qwen3.5-4B outputs**.
Rather than hand-editing a fixture, generate it from a successful run:

```bash
# 1. Take a 20-question run (if you haven't already)
llm-quality run --label baseline --n 20

# 2. Extract the fixture from the newest run
python3 scripts/make_fixture.py --latest

# 3. Run the tests
pytest
```

The fixture is written to `tests/fixtures/qwen_outputs.jsonl`. If it's missing,
the two regression tests **skip** (rather than fail), so CI stays green on a
fresh clone. The `make_fixture.py` script warns if the source run doesn't match
the reference case (18/20).

## What gets saved

Each run is stored as `~/gsm8k_results/runs/<label>_<timestamp>.json`:

```json
{
  "label": "baseline",
  "timestamp": "2026-11-05T18:00:00",
  "endpoint": "http://127.0.0.1:8080/v1/chat/completions",
  "model": "Qwen3.5-4B",
  "temperature": 0.0,
  "notes": "default config, greedy",
  "server_props": {
    "model_alias": "Qwen3.5-4B",
    "build_info": "b8681-...",
    "default_generation_settings": { "n_ctx": 65536, "temp": 0.0 }
  },
  "api_auth": false,
  "extra_headers_used": [],
  "results": [
    { "idx": 0, "gold": "18", "pred": "18", "correct": true,
      "elapsed_s": 53.1, "raw": "..." }
  ],
  "summary": { "correct": 18, "total": 20, "accuracy_pct": 90.0 }
}
```

## Extractor priority order

`extract_answer()` in `src/llm_quality_toolkit/extractor.py` applies four rules,
in this order:

1. `#### 42` — official GSM8K format
2. `\boxed{42}` — math-tuned models (last occurrence wins)
3. `**42**` — Qwen instruct models (last occurrence wins)
4. last number in text — fallback

This order was validated on 20 real Qwen3.5-4B outputs. See
[`docs/extraction-bug.md`](docs/extraction-bug.md) for why an earlier version
scored 62%, a "fix" scored 35%, and this one scores 90%.

## Troubleshooting

**`props: NOT AVAILABLE`** — The server doesn't expose `/props`, or the API key
was rejected. The run continues; only `server_args_manual` is recorded. This is
safe but less reproducible.

**`no runs found`** — `~/gsm8k_results/runs/` is empty. Run an evaluation first.

**`fixture missing` in tests** — The two regression tests skip until you run
`python3 scripts/make_fixture.py --latest`. This is intentional: a fresh clone
shouldn't fail CI just because it lacks user data.

**Authentication fails with a custom header** — Some servers expect the API key
in `X-API-Key` rather than `Authorization: Bearer`. Use `--header "X-API-Key: ..."`
instead of `--api-key`.
